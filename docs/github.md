# Publish with GitHub Desktop and GitHub Pages

## If the GitHub repository does not exist yet

1. Open GitHub Desktop and choose **File → Add Local Repository**, selecting this prepared source folder, not its parent directory containing private exports.
2. If it is not a Git repository yet, use the offered **create a repository here** option. Verify that the repository root is the folder containing this README, AGENTS.md and LICENSE, rather than a new empty subfolder. The suggested GitHub repository name is `claude-archive`.
3. Review the Changes list and make the initial commit. Include the hidden `.agents` and `.github` folders. Export ZIPs, generated archives, migration journals and logs are not source files and must not be committed.
4. Click **Publish repository**, choose the owner and name, and select public visibility if desired.

The local folder can have a different name from the GitHub repository. See [GitHub's existing-project guide](https://docs.github.com/en/desktop/adding-and-cloning-repositories/adding-an-existing-project-to-github-using-github-desktop).

## If you already created a repository on github.com

The straightforward Desktop workflow is to **clone that repository**, copy the prepared source files into the cloned folder (including `.agents`, `.github`, LICENSE and `.gitignore`), review the changes, commit and push. Do not copy over the clone's `.git` directory or include generated demo/archive/migration folders. There is no need to select the prepared folder as a second unrelated repository.

Alternatively, an existing local Git repository can be connected to the remote repository, but any README/license commits already on the remote need to be reconciled before pushing. Starting with an empty remote avoids that extra step.

## Enable only the fictional demo on Pages

1. Publish/push the source repository.
2. In the GitHub repository open **Settings → Pages**.
3. Under **Build and deployment**, set **Source** to **GitHub Actions**.
4. Open **Actions → Publish fictional demo → Run workflow** and select the default branch. An earlier run before enabling Pages may have failed; rerun after enabling it.
5. Wait for build and deploy to finish. The deployment summary and **Settings → Pages** show the actual published URL. For a normal project repository this is typically `https://OWNER.github.io/claude-archive/`.

The workflow builds on pushes to `main` or `master` and can be run manually. If your default branch has another name, update its branch filter. The builder uses a temporary export generated by `examples/make_demo.py`, then uploads only `site-demo/`. It does not read your local demo folders, private exports, or migration journals. Relative URLs support a repository subpath.

Visitors can search and browse chats, inspect available artifacts, download visible Markdown and change project assignments. Those assignments stay in their browser's localStorage. There is no export upload form or remote Codex import. A fresh browser or cleared site data resets the demo.

GitHub Pages serves static files and does not execute the local Python server. Python runs only during the build in Actions. See [GitHub Pages site creation](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).

## Preview before publishing

```sh
python3 build_demo_site.py --output site-demo
python3 -m http.server 8877 --bind 127.0.0.1 --directory site-demo
```

Open `http://127.0.0.1:8877/`. The builder requires a new/empty output folder; retain no visitor state in source files. The generated `site-demo/` folder is ignored by Git. For the full local archive use the normal `server.py` workflow instead.
